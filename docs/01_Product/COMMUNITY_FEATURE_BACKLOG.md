# 社区共建功能范围与后续规划

> **Status:** Accepted
> **Updated:** 2026-08-23
> **Scope:** 生态社区、意见反馈、需求池、团队风采、性能分析入口

本文记录社区共建相关功能的本期范围和已明确暂不开发的能力。开发状态以
`../00_Project/BASELINE_STATUS.md` 为准，实施顺序以
`../00_Project/ROADMAP.md` 为准。

## 1. 本期实现范围

### 1.1 生态社区

- 在平台顶部和首页提供社区入口；
- 社区名称和跳转地址由 `.env.platform` 配置；
- 第一批入口为 W3 负载建模社区和稼先社区；
- 后端只向前端返回允许公开的社区配置，不暴露其他环境变量；
- 外部链接仅允许 `http` 或 `https`，并在新窗口打开。

### 1.2 意见反馈

- 登录用户可以从任意页面提交意见反馈；
- 记录反馈类型、反馈内容、提交页面、提交人和提交时间；
- 反馈真实写入数据库；
- 本期不向普通用户展示反馈列表；
- 反馈记录仅管理员可通过受保护的后端接口读取，本期不开发管理员管理页面。

### 1.3 需求池

- 登录用户可以提交需求，需求真实写入数据库；
- 提交人可以查看自己提交的需求；
- 所有登录用户可以查看审视后设置为公开的需求；
- 新需求默认状态为“待审视”，默认仅提交人和管理员可见；
- 需求审视不开发管理界面，由可编辑配置文件维护公开范围、审视状态和结论；
- 需求池页面展示“公开需求 + 当前用户自己的需求”。

需求审视配置示例：

```yaml
demand_reviews:
  REQ-202608-001:
    visibility: public
    status: accepted
    conclusion: 已纳入下一版本规划
```

实际配置文件为 `backend/config/platform_content.yml`。部署环境可通过
`PLATFORM_CONTENT_CONFIG` 指向仓库外的配置文件。后端在读取团队页面或需求池时
重新加载该文件，修改后无需重新构建前端；配置文件需要由部署账号保持只读保护。

管理员从数据库或 `GET /api/admin/feedback` 读取反馈。该接口只允许管理员模式访问。

### 1.4 团队风采

- 提供团队简介、能力方向和成果展示页面；
- 展示内容由独立配置文件维护，修改内容不需要改动或重新构建前端代码；
- 本期不开发团队内容管理界面。

### 1.5 性能分析平台

- 增加 `/performance` 路由和导航入口；
- 页面只展示“功能建设中”的空状态；
- 不展示模拟分析结果，避免用户误认为分析能力已经可用。

## 2. 已规划但本期不开发

### 2.1 意见反馈后续能力

- 截图和附件上传；
- “我的反馈”页面；
- 反馈处理状态（待处理、处理中、已解决等）；
- 管理员反馈管理页面；
- 管理员回复和处理结论；
- 反馈状态变化通知；
- 反馈数据导出与统计。

### 2.2 需求池后续能力

- Web 端需求审视和状态管理；
- 管理员批量处理和需求合并；
- 需求评论、讨论和关注；
- 需求状态变化通知；
- 附件上传；
- 草稿保存；
- 需求排期、负责人和交付版本管理；
- 需求数据导出与统计。

### 2.3 团队风采后续能力

- Web 端团队内容管理；
- 成果详情页和成果发布流程；
- 成员档案、贡献榜自动统计；
- 与分析报告、Benchmark 和仿真成果自动关联。

### 2.4 性能分析后续能力

- 分析任务创建和历史记录；
- 仿真结果、Trace 和 Benchmark 数据源接入；
- 分析工具注册、调度和版本管理；
- 指令、内存、时间线和关键路径分析；
- 分析报告保存、导出、复核与发布；
- 对比基线和自动瓶颈发现。

## 3. 可见性原则

| 数据 | 提交人 | 其他登录用户 | 管理员 |
|---|---|---|---|
| 意见反馈 | 本期提交后仅显示成功提示 | 不可见 | 可通过受保护接口读取 |
| 待审视的需求 | 可见 | 不可见 | 可见 |
| 配置为公开的需求 | 可见 | 可见 | 可见 |
| 配置为私有的审视结论 | 可见 | 不可见 | 可见 |

## 4. 后续功能进入开发的条件

出现以下任一情况时，应重新评估上述后续能力的优先级：

- 反馈数量已无法通过数据库查询或人工流转有效处理；
- 需求数量或审视频率使配置文件维护容易出错；
- 用户需要跟踪处理进度或管理团队需要统一回复；
- 性能分析已有明确的数据源、分析工具和最小验收场景；
- 团队成果更新频率需要非研发人员自主维护。
